**동영상 파일 크기는 `비트레이트 × 길이 ÷ 8`로 정해집니다.** 해상도(화면 크기)나 화질 이름("HD", "FHD")이 크기를 직접 정하는 게 아닙니다. 비트레이트는 영상 1초에 몇 비트를 쓰느냐는 값이고, 영상을 줄이는 압축기(코덱)가 이 값을 목표로 맞춥니다. 또 "목표 화질"로 압축하면 비트레이트가 화면 내용에 따라 알아서 변해서, 같은 해상도·같은 길이도 크기가 수천 배 차이 납니다.

> 직접 돌린 환경: Linux 6.18, 4코어, ffmpeg 6.1.1(libx264 H.264 인코더), 테스트용 합성 영상. 실제 촬영 영상이 아니므로 숫자는 "원리 확인용"이고, 일반적인 크기로 받아들이면 안 됩니다.

## 1. 비트레이트를 정하고 인코딩하기

ffmpeg의 `-b:v`는 영상 비트레이트를 정합니다. [공식 문서](https://ffmpeg.org/ffmpeg-codecs.html)의 설명은 "Set bitrate in bits/s"입니다. 같은 1280x720, 30fps 합성 영상 10초를 1·4·8Mbps(초당 100만·400만·800만 비트)로 만들었습니다.

```bash
S="testsrc2=size=1280x720:rate=30"
ffmpeg -f lavfi -i "$S" -t 10 -c:v libx264 -b:v 4M -maxrate 4M -bufsize 4M -pix_fmt yuv420p b4M.mp4
```

파일 크기와 `ffprobe`로 읽은 길이·비트레이트입니다.

| 설정 | 길이 | 파일 크기(바이트) | 실제 비트레이트(bit/s) |
|---|---|---|---|
| 1Mbps, 10초 | 10초 | 1,279,774 | 1,023,819 |
| 4Mbps, 10초 | 10초 | 5,105,618 | 4,084,494 |
| 8Mbps, 10초 | 10초 | 10,032,218 | 8,025,774 |
| 4Mbps, **20초** | 20초 | 10,122,675 | 4,049,070 |

해상도는 모두 같은데 크기는 약 8배 차이가 납니다. 4Mbps로 길이만 2배(20초)로 하면 크기도 거의 2배가 됩니다.

계산으로 맞춰 보면 이렇습니다.

```
$ python3 -c "print(4e6*10/8, 4e6*20/8)"
5000000.0 10000000.0
```

예상 5,000,000·10,000,000바이트에 실제 5.1MB·10.1MB가 나왔습니다. 차이는 컨테이너(MP4 껍데기) 정보와 인코더의 비트 배분 오차 정도입니다. 같은 식으로 4Mbps면 1분 30MB, 8Mbps면 1시간 3.6GB입니다.

단위가 헷갈리면 [인터넷 속도 글](/posts/mbps-vs-mbs-download-speed/)처럼 **비트(b)와 바이트(B)** 를 구분하세요. 8비트가 1바이트라서 8로 나눕니다.

## 2. "화질 기준"으로 만들면 크기를 예측할 수 없다

비트레이트를 고정하지 않고 화질 수준만 정하는 방식도 있습니다. libx264에서는 `-crf`로, ffmpeg 도움말은 "Select the quality for constant quality mode"라고 설명합니다(`ffmpeg -h encoder=libx264`로 확인). 같은 `-crf 23`에 화면 내용만 바꿔 10초씩 만들었습니다.

| 화면 내용 | 파일 크기(바이트) | 비트레이트(bit/s) |
|---|---|---|
| 단색 회색 화면 | 17,428 | 13,942 |
| 테스트 패턴(움직이는 도형·글자) | 3,776,719 | 3,021,375 |
| 프레임마다 완전히 무작위인 잡음 | 109,487,344 | 87,589,875 |

해상도·길이·화질 설정이 모두 같은데 17KB에서 109MB까지 갑니다. 압축기는 앞뒤 화면이 비슷할수록 "달라진 부분만" 저장해서 비트를 아끼기 때문입니다. 안 변하는 화면은 거의 공짜고, 매 프레임이 전부 달라지는 화면은 압축할 여지가 없습니다. 같은 이유로 실제 영상도 정적인 강의 화면과 빠르게 움직이는 스포츠 중계의 크기가 다릅니다. (이 표의 극단값은 합성 입력이라 그런 것이고, 실제 영상이 이 범위의 끝에 가는 건 아닙니다.)

## 정리

- 크기 ≈ 비트레이트 ÷ 8 × 초. 영상 편집·내보내기 화면에 비트레이트 칸이 있으면 이 식으로 먼저 예상할 수 있습니다.
- 비트레이트를 고정하면 크기는 예측되지만 화질은 내용에 따라 달라지고, 화질을 고정하면 화질은 일정하지만 크기는 예측이 안 됩니다.
- 이 글의 측정은 H.264(libx264)만 돌렸습니다. 다른 코덱에서 같은 비트레이트가 어떤 화질이 되는지는 확인하지 않았습니다.
