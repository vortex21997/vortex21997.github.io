**결론:** 복사 시간은 **전체 용량**만이 아니라 **파일 개수**에도 비례한다. 파일 하나를 복사할 때마다 "열기 → 정보 확인 → 복사 → 닫기"라는 고정 작업이 붙는데, 이 비용은 파일이 10KB든 100MB든 비슷하다. 같은 100MB라도 파일 하나면 이 작업을 한 번, 1만 개면 1만 번 치른다.

> 용어: **시스템 콜**은 프로그램이 운영체제에게 "파일 열어줘", "이만큼 복사해줘"처럼 일을 부탁하는 창구다. 프로그램은 디스크를 직접 만지지 않고 반드시 이 창구를 거친다.
{: .prompt-info }

## 같은 100MB, 다른 파일 개수

샌드박스에서 100MB를 두 가지 모양으로 만들었다. 하나는 100MB 파일 1개, 다른 하나는 10KB 파일 1만 개다.

```bash
head -c 100000000 /dev/urandom > one/big.bin
for i in $(seq 1 10000); do head -c 10000 /dev/urandom > many/f$i.bin; done
du -sb many one
```

```
100000000	many
100000000	one
```

폴더 용량은 정확히 같다. 이걸 `cp -r`로 세 번씩 복사해 시간을 쟀다(`time`, 매번 `sync` 후).

```
one  0.049 s
many 0.217 s
one  0.046 s
many 0.210 s
one  0.058 s
many 0.217 s
```

파일 1만 개 쪽이 4배쯤 느렸다.

> 측정 환경: Linux 6.18.44, 4코어, ext4, GNU coreutils cp 9.4. 방금 만든 파일이라 읽기는 메모리 캐시에서 일어난다. 실제 하드디스크나 USB, 네트워크 드라이브에서는 배율이 크게 달라질 수 있어서 "4배"를 일반화하면 안 된다.
{: .prompt-warning }

## 4배 차이는 어디서 나왔나

`strace -c`는 프로그램이 호출한 시스템 콜을 종류별로 세어 준다. (`strace` 사용법은 [man 페이지](https://man7.org/linux/man-pages/man1/strace.1.html) 참고.)

```bash
strace -f -c -o s1.txt cp -r one d1_s
strace -f -c -o s2.txt cp -r many d2_s
```

총합 줄만 보면 이렇다.

| | 시스템 콜 횟수 | 그중 `openat`(파일 열기) | `copy_file_range`(내용 복사) |
|---|---|---|---|
| 파일 1개 | 105 | 11 | 2 |
| 파일 1만 개 | 110,109 | 20,009 | 20,000 |

데이터는 같은 100MB인데 운영체제에게 한 부탁은 **1,000배 넘게** 많다. `copy_file_range`는 [man 페이지](https://man7.org/linux/man-pages/man2/copy_file_range.2.html)에 따르면 한 파일 안의 데이터를 다른 파일로 옮기는 호출이다. 파일 1개짜리는 이 호출 두 번으로 100MB가 끝나고, 1만 개짜리는 파일마다 따로 불러야 한다. `openat`, `close`, `fstat`(크기·권한 확인)도 파일마다 반복된다.

그래서 시간이 정확히 1,000배가 되지는 않는다. 호출 한 번이 가볍기 때문이다(1만 개 쪽은 호출당 평균 약 13마이크로초). 대신 이런 고정 비용이 쌓여서 0.05초가 0.21초가 됐다. 이 수치는 `strace` 자체가 느리게 만든 값이 섞여 있어서 위 `time` 측정과 직접 비교하지는 않는다. 비교할 건 횟수다.

## 판별법: 내 복사가 느린 이유가 개수 탓인가

- 용량은 작은데 복사 창이 "남은 항목 수천 개"로 오래 걸린다 → **개수 비용**이다. 코드 프로젝트 폴더(`node_modules` 등)가 대표적이다.
- 파일 개수는 적은데 용량이 크고 속도(MB/s)가 일정하게 낮다 → **용량 비용**이다. 드라이브나 연결 방식의 최대 속도가 한계다.

개수 비용을 줄이는 쉬운 방법은 **폴더를 하나의 압축 파일로 묶어서 옮기는 것**이다. 옮기는 동안은 큰 파일 1개처럼 다뤄지고, 풀 때 한 번만 파일을 만든다.

## 확인한 것과 못 한 것

- **직접 돌려 확인:** 위 시간 측정과 `strace -c` 시스템 콜 횟수.
- **확인 못 함:** 하드디스크·USB·네트워크 드라이브에서의 배율. 이 샌드박스에서는 측정하지 않았다.
