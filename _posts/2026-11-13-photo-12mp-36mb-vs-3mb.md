**결론부터:** 사진을 **화소(픽셀, 화면을 이루는 점 하나)** 수로 계산하면 1200만 화소 사진은 약 34MiB지만, 실제 파일은 보통 몇 MiB에 그친다. 파일로 저장할 때 **압축**하기 때문이다. 압축 안 한 크기는 해상도만 알면 계산되고, 실제 크기는 압축 방식과 그림 내용에 따라 달라진다.

## 계산: 압축하지 않으면

한 화소는 빨강·초록·파랑 값을 각각 1바이트씩, 모두 3바이트로 적는다. 가로 4000 × 세로 3000이면 다음과 같다.

```
12,000,000 화소 × 3바이트 = 36,000,000바이트 ≈ 34.33 MiB
```

## 직접 확인

같은 이미지를 형식별로 저장해 크기를 쟀다. 환경은 Python 3.11.18, Pillow 13.0.0, 4코어 리눅스 샌드박스다. 이미지는 노이즈와 그라데이션을 흐리게 섞어 **직접 만든 합성 이미지**(실제 사진이 아님)와 한 가지 색으로 채운 이미지, 두 가지다.

| 파일 | 바이트 | MiB |
|---|---|---|
| 합성 이미지 `.bmp` (압축 없음) | 36,000,054 | 34.33 |
| 합성 이미지 `.png` | 6,487,559 | 6.19 |
| 합성 이미지 `.jpg` quality=95 | 2,554,212 | 2.44 |
| 합성 이미지 `.jpg` quality=85 | 1,487,043 | 1.42 |
| 합성 이미지 `.jpg` quality=50 | 831,013 | 0.79 |
| 단색 `.bmp` | 36,000,054 | 34.33 |
| 단색 `.png` | 42,238 | 0.04 |

- BMP는 계산값 36,000,000바이트에 머리 정보 54바이트만 더해졌다. 압축하지 않는 형식은 계산대로 나온다.
- 단색 BMP와 합성 BMP의 크기가 **똑같다.** 압축이 없으면 그림 내용은 크기에 영향을 주지 못한다.
- PNG는 정보를 잃지 않는 압축이라 내용에 크게 좌우된다. 단색은 0.04MiB, 합성 이미지는 6.19MiB였다.
- JPEG는 사람 눈에 덜 띄는 정보를 버리는 압축이다. `quality`를 낮출수록 작아졌다(95 → 50에서 약 3분의 1).

> 이 수치는 합성 이미지 한 장에서 잰 값이다. 실제 사진은 내용에 따라 달라지므로 "JPEG는 항상 이 비율"로 일반화할 수 없다.
{: .prompt-warning }

## 그래서 알게 되는 것

- 해상도(화소 수)는 **압축 전 크기의 상한 계산**에 쓴다. 파일 크기를 정하는 건 형식과 내용이다.
- 같은 화소 수라도 하늘처럼 단순한 사진은 작고, 잔디나 잎처럼 자잘한 무늬가 많은 사진은 크다.
- 화질 손실이 없는 형식이 필요하면 PNG처럼 정보를 잃지 않는 형식을, 크기가 우선이면 JPEG를 쓴다.

## 근거

- JPEG 저장 시 `quality` 옵션: [Image file formats (Pillow 문서)](https://pillow.readthedocs.io/en/stable/handbook/image-file-formats.html)
- JPEG 표준: [ITU-T T.81](https://www.w3.org/Graphics/JPEG/itu-t81.pdf)
