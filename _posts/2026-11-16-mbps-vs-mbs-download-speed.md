**결론부터:** 회선 속도의 **Mbps**는 초당 메가**비트**, 다운로드 창의 **MB/s**는 초당 메가**바이트**다. 1바이트는 8비트라서 500Mbps는 이론상 62.5MB/s다. 거기에 데이터 앞에 붙는 **헤더**(주소·순서 등을 적는 머리말) 비용이 더해져 실제 화면에는 이보다 조금 낮게 보인다. 속도가 안 나오는 게 아니라 단위가 다른 것이다.

> 확인 환경: Python 3.11.18, curl 8.5.0, Linux 6.18 샌드박스 (4코어). 실제 회선은 재지 못했고, 계산과 단위 확인만 한 글이다.
{: .prompt-info }

## 계산: 8로 나눈다

**비트(bit)**는 0 또는 1 하나, **바이트(byte)**는 8비트 묶음이다. 파일 크기는 바이트로, 회선 속도는 관례상 비트로 적는다.

```console
$ python3 -c 'print(500/8, "MB/s")'
```

```text
62.5 MB/s
```

(여기서 M은 10⁶이다. 같은 MB/s라도 브라우저·OS가 2²⁰ 기준(MiB)으로 보여 주면 숫자가 더 작아진다.)

```console
$ python3 -c 'print(62.5e6/2**20)'
```

```text
59.604644775390625
```

500Mbps가 59.6MiB/s로도 표시될 수 있다는 뜻이다. 1TB가 931GB로 보이는 것과 같은 단위 문제는 [1TB 하드가 931GB로 보이는 이유]({% post_url 2026-10-30-1tb-shows-931gb %})에서 다뤘다.

## 직접 확인: curl은 바이트로 보고한다

로컬(127.0.0.1)에서 200MB 파일을 받으며 curl의 속도 항목을 찍었다.

```console
$ curl -s -o /dev/null -w 'size_download=%{size_download} time_total=%{time_total} speed_download=%{speed_download}\n' http://127.0.0.1:8765/big.bin
```

```text
size_download=200000000 time_total=0.117832 speed_download=1697331794
```

`speed_download`는 **초당 바이트**다. 200000000 ÷ 0.117832 = 약 1.697×10⁹, 출력값과 맞다. 다운로드 도구가 바이트 단위로 보고한다는 점을 눈으로 확인한 것이고, 이 값(약 1.7GB/s)은 루프백 측정이라 회선 속도와는 무관하다.

## 헤더 비용

전송되는 데이터는 조각(패킷)으로 나뉘고, 조각마다 헤더가 붙는다. 근거는 다음과 같다.

- 이더넷으로 보낼 수 있는 IP 데이터그램의 최대 길이는 1500옥텟이다. [RFC 894](https://www.rfc-editor.org/rfc/rfc894.txt)에 적혀 있다.
- IPv4 헤더는 [RFC 791](https://www.rfc-editor.org/rfc/rfc791.txt)의 IHL 필드(32비트 단어 수)로 길이가 정해지고, TCP 헤더는 [RFC 9293](https://www.rfc-editor.org/rfc/rfc9293.txt)의 Data Offset 필드(32비트 단어 수)로 정해진다. 옵션이 없을 때 최소값은 둘 다 20바이트다. (최소값 20바이트는 두 문서의 헤더 그림에서 5단어로 읽은 것이다.)

옵션이 없다고 가정하면 1500바이트 중 실제 내용은 1500 − 20 − 20 = 1460바이트다.

```console
$ python3 -c 'print(1460/1500, 500/8*1460/1500)'
```

```text
0.9733333333333333 60.83333333333333
```

500Mbps 회선에서 약 60.8MB/s, 즉 97.3%가 내용에 쓰인다. 이더넷 프레임 자체의 머리말과 패킷 사이 간격까지 넣으면 더 낮아지지만, 그 값은 이 글에서 직접 확인하지 못해 계산에서 뺐다. 요점은 "62.5MB/s에서 몇 퍼센트 깎이는 것은 정상"이라는 것이다.

## 판별법: 단위 때문인가, 진짜로 느린가

| 화면 숫자 | 원인 |
|---|---|
| 회선의 1/8에서 헤더 몇 % 뺀 값 근처 (500Mbps → 55~62MB/s) | 정상. 단위 차이 |
| 그보다 훨씬 낮음 | 와이파이, 서버 쪽 제한, 디스크 속도 등 다른 병목 |

단위를 먼저 맞춰 놓고 비교하면 "느리다"는 판단이 달라진다. 회선 숫자를 8로 나눈 값이 기준선이다.
