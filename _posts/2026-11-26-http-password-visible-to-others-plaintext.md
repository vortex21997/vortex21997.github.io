결론부터. 주소가 `http://`로 시작하는 사이트에 로그인하면 아이디와 비밀번호가 **암호화 없이 글자 그대로** 인터넷을 지나간다. 같은 와이파이를 쓰는 사람이나 중간 장비가 그 길목에서 데이터를 받아 볼 수 있으면 비밀번호를 그냥 읽는다. `https://`는 같은 요청을 암호화해서 보내기 때문에 길목에서는 알아볼 수 없는 바이트만 보인다.

"주소창 자물쇠가 있으면 안전한 사이트인가"와는 다른 질문이다. 여기서는 **길을 지나는 동안 내용이 보이느냐**만 본다.

> 용어: **평문**은 암호화하지 않은, 사람이 그대로 읽을 수 있는 데이터다. **프록시(중계기)**는 오가는 데이터를 중간에서 받아 전달하는 프로그램이다. 아래 실험에서는 와이파이 옆자리의 누군가를 대신해서 쓴다.
{: .prompt-info }

## 실험: 같은 로그인을 중간에서 받아 보기

내 컴퓨터 안에 서버 둘(http용, https용)과 그 앞에 단순한 중계기를 세우고, `curl`로 같은 로그인 정보를 보낸 뒤 **중계기가 받은 바이트**를 저장했다. 외부 네트워크는 쓰지 않고 한 컴퓨터 안에서만 돌렸다. 아이디 `minsu`, 비밀번호 `hunter2`는 실험용 값이다.

환경: 샌드박스(Linux), curl 8.5.0, OpenSSL 3.0.13, Python 3.11.18. https 서버는 직접 만든 임시 인증서를 써서 `curl -k`(인증서 검증 생략)로 접속했다. 인증서 검증은 이 실험의 주제가 아니다.

```bash
curl -s -d 'id=minsu&password=hunter2' http://127.0.0.1:8081/login
curl -sk -d 'id=minsu&password=hunter2' https://127.0.0.1:8443/login
```

### http: 중계기가 받은 177바이트

```text
POST /login HTTP/1.1
Host: 127.0.0.1:8081
User-Agent: curl/8.5.0
Accept: */*
Content-Length: 25
Content-Type: application/x-www-form-urlencoded

id=minsu&password=hunter2
```

요청 전체가 읽힌다. 어느 주소의 어떤 경로로 보냈는지, 아이디와 비밀번호가 무엇인지 모두 그대로다. 이 형식은 HTTP 규격이 정한 텍스트 메시지다([RFC 9112](https://www.rfc-editor.org/rfc/rfc9112)).

### https: 중계기가 받은 820바이트

저장된 바이트의 앞부분이다.

```text
0000  16 03 01 02 00 01 00 01 fc 03 03 d8 71 25 a4 48  ............q%.H
0010  6a 6d d8 f3 73 8e 28 2c 11 21 af aa 86 31 9e 19  jm..s.(,.!...1..
0020  e7 ae 27 65 b4 d5 2a f1 1c f5 77 20 6b 28 7d 98  ..'e..*...w k(}.
```

글자로 읽히는 부분이 없다. 파이썬으로 `hunter2`, `password`, `POST`를 찾았더니 셋 다 없었다(`False False False`). 첫 바이트 `16`은 "암호 연결을 맺는 중"이라는 표시이고 TLS라는 암호화 규격의 일부다([RFC 8446](https://www.rfc-editor.org/rfc/rfc8446)). 로그인 내용은 연결이 맺어진 뒤 암호화된 덩어리로 실려 간다.

## 이 결과로 말할 수 있는 것과 없는 것

- **말할 수 있는 것:** 같은 요청이라도 http는 내용이 길목에서 읽히고, https는 읽히지 않았다.
- **말할 수 없는 것:** 실제 카페 와이파이에서 남의 데이터를 받을 수 있는지는 이 실험이 보여 주지 않는다. 내 컴퓨터 안에서 중계기를 일부러 끼운 것이다. 그 조건이 실제로 얼마나 쉬운지는 확인하지 않았다.
- 접속한 주소가 IP여서 이번 캡처에는 사이트 이름이 보이지 않는다. https일 때 길목에서 무엇이 더 보이는지는 직접 확인하지 않아 쓰지 않는다.

## 직접 확인하는 법

주소창에 `http://`가 있거나 "주의 요함 / 안전하지 않음"이 뜨는 사이트에서는 비밀번호나 카드 번호를 입력하지 않는 편이 안전하다. 그 주소가 `https://`로도 열리는지 먼저 본다. 열리면 `https://`로 접속하면 된다.
