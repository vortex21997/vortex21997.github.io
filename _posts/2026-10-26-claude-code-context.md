> **2026-10 기준.** [비용 관리 문서](https://code.claude.com/docs/en/costs)를 근거로 정리했다.
{: .prompt-info }

세션을 아침에 열어두고 하루 종일 쓰다 보면 이런 일이 생긴다.
한 줄짜리 질문을 던졌는데 사용량이 훅 빠진다.

버그가 아니라 **구조상 당연한 일**이다.

## 왜 그런가

Claude Code는 **요청마다 대화 전체를 같이 보낸다.**
그리고 Claude가 도구를 쓸 때마다 그 결과를 담아 또 요청을 보낸다.

그래서 하루 종일 열어둔 세션에서 한 줄을 물으면,
**그 한 줄이 아니라 하루치 대화가 통째로 움직인다.**

프롬프트 캐시가 있어서 다시 읽는 비용은 할인되지만, **공짜는 아니다.**

## 캐시가 식으면 더 커진다

여기서 한 겹 더 있다. 캐시에는 수명이 있다.

> 휴식 후 보내는 첫 메시지가 [캐시 수명](https://code.claude.com/docs/en/prompt-caching)보다 오래 비어 있었다면,
> 캐시를 놓치고 전체 컨텍스트를 **다시 처리한다.**

점심 먹고 와서 던진 첫 질문이 유독 오래 걸리고 비싸게 먹히는 이유다.

`/usage`를 열면 캐시 상태를 직접 볼 수 있다.

```text
Prompt cache (main):   14 requests · 91% of input tokens from cache · 2 misses
                       · warm (1h TTL, last activity 40s ago)
```

`warm`이면 아직 살아 있는 것이고, `cold`면 다음 요청이 전체를 다시 읽는다.

## 세션이 조용해도 돈이 나가는 경우

가만히 뒀는데도 사용량이 올라간다면 이 중 하나다.

| 원인 | 설명 |
|---|---|
| 예약 작업 | 세션에 묶인 스케줄이 유휴 상태에서도 주기마다 발동한다. 그때마다 전체 컨텍스트를 보낸다 |
| 다른 세션의 메시지 | 내 다른 세션이 보낸 메시지가 새 턴으로 전달된다 |
| 서브에이전트 | 메인 대화와 별개로 자기 요청을 보낸다 |
| 에이전트 팀 | 팀원 하나하나가 자기 컨텍스트 창을 유지한다. 종료할 때까지 계속 쓴다 |

`/loop`를 걸어두고 잊어버린 게 제일 흔하다. `/usage`에 Loops 행으로 나온다.

## /clear 와 /compact — 뭐가 다른가

둘 다 컨텍스트를 비우는 것처럼 보이지만 **성격이 정반대**다.

| | `/compact` | `/clear` |
|---|---|---|
| 하는 일 | 지금까지 대화를 **요약**해서 자리를 비운다 | 컨텍스트를 **버리고** 새로 시작 |
| 연속성 | 유지된다 | 끊긴다 |
| 비용 | **요약할 대화를 다 읽어야 한다 → 큰 요청** | **공짜** |

여기가 핵심이다.

> `/compact`는 요약할 대화를 읽으므로, **큰 컨텍스트를 압축하는 것 자체가 큰 요청**이다.
> 연속성이 필요 없고 새로 시작해도 된다면 `/clear`가 비용이 들지 않는다.

**판단 기준은 하나다. 앞의 맥락이 다음 작업에 필요한가?**

- 필요하다 (같은 기능을 계속 만드는 중) → `/compact`
- 필요 없다 (다른 일로 넘어감) → **`/clear`**

관련 없는 작업으로 넘어가면서 `/compact`를 하는 게 제일 아까운 경우다.
쓰지도 않을 맥락을 돈 내고 요약해서 들고 가는 셈이다.

### 요약할 때 뭘 남길지 정할 수 있다

```text
/compact 코드 예제와 API 사용법 위주로 남겨줘
```

`CLAUDE.md`에 적어두면 매번 안 쳐도 된다.

```markdown
# Compact instructions

압축할 때는 테스트 출력과 코드 변경 위주로 남긴다
```

### 세션을 잃지 않고 비우기

```text
/rename 블로그-테마-작업
/clear
```

나중에 `/resume`으로 돌아오면 된다. 이름을 안 붙이고 비우면 목록에서 찾기 어렵다.

## 뭐가 자리를 먹는지 보기

추측하지 말고 `/context`를 치면 색깔 격자로 나온다.
자주 범인으로 지목되는 건 두 가지다.

**① 비대한 `CLAUDE.md`**
세션 시작할 때 통째로 들어가고, **관련 없는 작업을 할 때도 계속 들어 있다.**
공식 권장은 **200줄 이하**다. 특정 워크플로용 긴 지시(PR 리뷰 절차, DB 마이그레이션 순서)는
스킬로 빼면 필요할 때만 로드된다.

**② MCP 서버**
도구 정의가 기본적으로 지연 로딩되긴 하지만, 안 쓰는 서버는 `/mcp`에서 끄는 게 낫다.
`gh`, `aws`, `gcloud` 같은 **CLI가 있으면 그쪽이 컨텍스트 효율이 더 좋다.** 도구 목록을 아예 안 싣는다.

## 훅으로 미리 걸러내기

컨텍스트를 아끼는 방법 중 제일 효과가 큰 건 **Claude가 보기 전에 줄이는 것**이다.

로그 1만 줄을 읽게 하는 대신, 훅이 `ERROR`만 뽑아서 넘기면
수만 토큰이 수백으로 준다.

```json
{
  "hooks": {
    "PreToolUse": [{
      "matcher": "Bash",
      "hooks": [{ "type": "command", "command": "~/.claude/hooks/filter-test-output.sh" }]
    }]
  }
}
```

같은 이유로 **시끄러운 작업은 서브에이전트에 맡긴다.**
출력이 서브에이전트 창에 남고 요약만 돌아온다.

## 정리

| 증상 | 볼 곳 |
|---|---|
| 짧은 질문인데 비싸다 | 세션이 길다 → `/clear` |
| 쉬었다 온 첫 요청이 느리다 | 캐시가 식었다. 구조상 그렇다 |
| 가만히 뒀는데 올라간다 | `/usage`의 Loops·서브에이전트 행 |
| 뭐가 자리를 먹는지 모르겠다 | `/context` |
| 매 요청이 무겁다 | `CLAUDE.md`가 길거나 MCP 서버가 많다 |

습관 두 개로 대부분 해결된다. **관련 없는 작업 사이에 `/clear`**,
그리고 **작업에 맞는 모델 고르기.** 공식 문서도 이 둘을 가장 영향이 큰 습관으로 꼽는다.
